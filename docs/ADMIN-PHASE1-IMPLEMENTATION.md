# Phase 1 admin implementation — staged, not live

The source branch contains Cloudflare Access JWT verification at `/api/admin/session`, a D1 allowlist (`admin_identities`), hashed opaque server sessions, secure HttpOnly SameSite cookies, revocation/logout, an active-state check on every request, and server-validated admin page/API boundaries. A Cloudflare Access application must protect the preview admin sign-in path and API. Configure `ACCESS_TEAM_DOMAIN` (the exact https team domain) and `ACCESS_AUD` from that application. Seed only the designated Teams administrative email(s) into `admin_identities`, never a guessed address. The account's Access policy must allow exactly those identities; the D1 allowlist is a second gate.

Additive migration: `src/lib/migrations/admin-phase1.sql`. Apply it to the isolated preview D1 before deploying this code; it creates no authorized identity. Existing contact submissions remain in D1. Configure `INQUIRY_NOTIFICATION_EMAIL`, `INQUIRY_FROM_EMAIL`, and `RESEND_API_KEY` only after the receiving inbox and sender are approved and verified. The Contact form remains closed until deployed admin review and delivery/error QA pass. A submission's D1 transaction creates `pending` notification state, then an asynchronous attempt records `sent`, `failed`, or `unknown`; a missing config remains `pending`. No private message body is included in notification email.

Preview deployment is intentionally not performed: this runtime's Cloudflare D1 API returned code 7403, so the migration could not be inspected or applied, and no live admin CRUD assertion can be made. The verified preview remains at commit `ca07106` until access is restored. R2 remains unavailable; no private media fallback is allowed.
